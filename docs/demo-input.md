# Demo input preparation

The setup chat uses real API replies from OpenRouter's `openai/gpt-6-luna`. It collects the
user's choices, shows a review, and saves the configuration consumed by the existing optimizer.
The setup screen does not train models, download datasets, or launch the optimizer.

## Start the chat

From `ml-agent/`:

```bash
.venv/bin/python -m rsi_ml.intake --port 8766 --env-file ~/.config/rsi_ml/api.env
```

The server reads `OPENROUTER_API_KEY` from the specified file; the browser never receives the
key. Open `http://127.0.0.1:8766` and click **New experiment**. Keep
[`demo-input-script.txt`](demo-input-script.txt) beside the recording window and manually type
one message per turn. The page has no recommended-reply buttons.

## Six-step flow

1. Describe the task: improve an MLP for forest cover classification.
2. Choose the registered UCI Covertype dataset.
3. Confirm seven-class prediction, measured by accuracy.
4. Confirm the existing 60/20/20 training/validation/test split.
5. Set a training-compute budget and maximum parameter count.
6. Review the configuration and say **Start**.

The model interprets each message and generates its reply. The six-step flow and supported
Covertype settings are fixed for this demo. The model checks whether answers fit the supported task; the server validates structured replies,
step transitions, resource limits, and the completed config. The model does not invent
dataset inspection, run training tools, or generate performance results during setup.

## Configuration and output

The setup inherits `configs/study/mlp-covertype-600s.json`, preserving the starting model,
training recipe, agent model, artifact policy, and constraint-based search. The review selects
a single D run at seed 2. It records the source protocol hash and the accepted settings.
The per-experiment cap follows the existing 4:9 rule: 267 seconds for a 600-second total budget.
The score target remains null for the existing baseline-based derivation.

`configs/study/intake-<timestamp>-<id>.json` is the actual runner protocol.
`intake_sessions/` retains the conversation and exact config hash. Files use unique names;
existing studies are not overwritten. Policy and template paths remain relative to
`configs/study/`, so transfer the config with the checkout rather than moving it alone.

Dataset metadata comes from the registered UCI source. The setup does not inspect uploaded
data or download Covertype. The existing GPU runner later fetches or reuses the pinned dataset
and constructs the agreed splits.

## Demo handoff

The final **“Starting…”** reply marks the end of setup. The page also states that the
configuration was saved and optimization has not launched; the saved record has
`execution_started: false`. Inspect or download the JSON from the page.

A real optimization run must subsequently be launched on the GPU VM through the existing
`autopilot` entry point with its own output directory. For the video, cut here to clearly
labeled playback of the completed real D/seed-2 run. Those recorded results are not new
results from this setup session.
